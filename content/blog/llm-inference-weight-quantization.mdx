前三篇处理了 KV cache 与串行解码，这一篇补最后一条轴：**权重本身的位宽**。

选它的原因直接来自第一篇的实测：短上下文、小 batch 时，KV 读取只占每步访存的 4%~9.5%，主导项始终是权重读取（7B 模型 bf16 每步约 15.3 GB）。不压权重，就动不了这个主导项。

四篇方法论文不是并列的四个点，是一条连续的叙事：

```
LLM.int8() (2022)   发现激活离群值 → INT8 直接量化在 13B 崩溃
SmoothQuant (2023)  把量化难度从激活搬到权重 → W8A8 可用
GPTQ (2023)         用二阶信息补偿量化误差 → 3/4 bit 可用
AWQ (2024)          用激活幅值挑出显著通道 → 部署成本压到最低
```



## 一、平台判据先立住

量化方法的"能不能用"首先取决于硬件有没有对应通路，而不是精度掉多少。两张目标卡的判据：

| 路线 | A800（sm80，80 GB） | RTX 4090（sm89，24 GB） | 判断 |
|---|---|---|---|
| **W4A16**（AWQ / GPTQ-4bit） | 可用，反量化回 FP16 再乘 | 可用 | **优先跑**，两卡都不依赖特殊张量核 |
| **W8A8**（SmoothQuant） | 可用，INT8 张量核 sm80 原生支持 | 可用，sm89 同样支持 | 可用，需核实 vLLM 版本是否带这条路径 |
| LLM.int8() | 可用，但端到端无收益 | 可用，但 7B 档更可能为负 | 只作背景，不作实验对象 |
| W4A8 / KV4 / FP4 | **不可用**，依赖 Hopper 级路径 | **不可用** | 跳过 |

W4A8、KV4、FP4 与 FlashAttention-3 被排除是同一条理由：A800 与 4090 都没有 Hopper 的低精度计算路径。

## 二、同一条物理事实被撞见四次

四篇论文各自独立地撞见了同一件事，这是整个量化族最有意思的结构：

- **LLM.int8()**：激活里 0.1% 的维度幅值是其他维的 3~20 倍，它们把统一的 scale 拉爆；
- **SmoothQuant**：这些离群值集中在**固定通道**上，所以可以把尺度按通道迁到权重侧；
- **AWQ**：权重的显著性由它乘上的激活决定，所以按**激活幅值**选通道做保护；
- **PTQ 综述**：把这条概括成"量化误差高度集中"，它是显著度族有效的前提。

四句话指向同一个结论：**能压到多低，取决于模型结构和硬件已有通路，而不是算法有多聪明。** KV 量化在 MQA 结构上 2-bit 失效（KIVI）、W4A8 在 Ampere/Ada 上不可用，都是这条规律的两个例子。

## 三、LLM.int8()：离群值这条线的起点

**出处**：NeurIPS 2022，arXiv:2208.07339v2 | **开源**：`TimDettmers/bitsandbytes`（随 transformers 一起装） | **平台**：A100 / A6000 / T4，BLOOM-176B 用到 8×A100 80GB

**问题**：INT8 的 absmax 量化在 6.7B 以下工作正常，到 13B 突然崩溃——13B 上 INT8 困惑度 19.08，反而高于 6.7B 的 14.59。崩溃不是量化算法的问题，是激活里存在**系统性离群特征维**：其他特征范围约 ±3.5，而 13B 的离群维四分位在 −63、−58、−45。它们把 per-tensor 的 scale 抬得过高，其余维度全部落到少数几个量化级上。

**方法**：

1. **absmax 分块量化**：按块求绝对最大值，块内共享一组 scale，避免单个离群值污染整个张量。
2. **离群维判据**：幅值不低于 6.0、出现在至少 25% 的层、覆盖至少 6% 的序列维。
3. **混合精度分解**：命中的离群维单独走 FP16 计算，其余走 INT8，两路结果相加。这一路开销很小——离群维只占约 0.1%。
4. 为速度做的工程：权重预量化、矩阵乘按行/列主序分别处理，避免在线转置。

**结果**：

| 项 | 数字 |
|---|---|
| 精度 | 13B 困惑度 12.45，与 32 位基线 12.45 **相等** |
| 相变位置 | 6B → 6.7B：受影响层 65% → 100%，序列维 35% → 75% |
| 离群维的作用 | 置零后 top-1 softmax 40% → 20%，困惑度 +600~1000%；随机置零 7 维仅 −0.02%~0.3% |
| 显存 | BLOOM-176B 1.96×；整体约 50% |
| **端到端** | BLOOM-176B、8×A100、batch 32：**10.44 ms/token（INT8）对 9.94（bf16），反而更慢** |
| 单层 GEMM | 13B 1.22×、175B 1.81×、**6.7B 0.86×（负收益）**、768 维 **0.14×** |

**结论**：这是一篇显存路线的论文，不是速度路线的论文——端到端与 bf16 持平或慢 5%~6%，唯一的加速数字来自单层 GEMM，且 6.7B 以下为负。开题里只能引"显存减半、精度不掉"，不能引加速比。

第二个结论更有用：**加速呈强维度阈值效应**。纯 INT8 GEMM 在 12288 维达 2.29×，加上量化开销后 5140 维只剩 1.59×，768 维掉到 0.14×。A800 / 4090 的解码阶段矩阵乘的 m 维很小（batch × 序列长度），预期正落在 0.6~0.9× 这一段——**这正好是可以自测、且文献没测过的区间**，是"硬件感知"这条创新点最直接的实测素材。

## 四、SmoothQuant：把难度从激活搬到权重

**出处**：ICML 2023，arXiv:2211.10438 | **开源**：`mit-han-lab/smoothquant` | **平台**：A100 80GB，530B 实验单节点 8 卡

**问题**：激活比权重难量化。权重训练后固定、分布平滑；激活随输入变化，且被 LayerNorm / RMSNorm 的输出放大出通道级离群值。per-tensor 的 INT8 激活在 OPT-175B 上直接把精度打崩，导致 W8A8 长期不可用——只能用 W8A16，白白浪费 INT8 张量核的算力。

**方法**：一个数学上完全等价的变换：

$$
X \cdot W = (X / s) \cdot (s \cdot W)
$$

把激活的量化难度按通道搬到权重上。迁移强度取：

$$
s_j = \frac{\max|X_j|^{\alpha}}{\max|W_j|^{1-\alpha}}
$$

$\alpha$ 是超参，一维搜索即可：$\alpha = 0$ 不迁移，$\alpha = 1$ 全迁到权重。落地三个要点：

1. **零运行时开销**：s 直接折进前一层（通常是 LayerNorm）的参数里，推理时没有额外算子。
2. **校准便宜**：Pile 上随机取 512 句，离线一次完成，全程不需要重训。
3. **系统是真的**：写了 INT8 GEMM kernel 与 PyTorch 侧实现，不是仿真。

**结果**：

| 项 | 数字 |
|---|---|
| OPT-175B 精度 | 七任务平均 66.9% → 66.8%；WikiText PPL 10.99 → 11.17 |
| Llama-2-70B | PPL 3.320 → 3.359 |
| INT8 GEMM 加速 | 最高 **1.56×**，基线 FasterTransformer-FP16 |
| 解码逐 token 延迟 | 最高 **1.42×**（OPT-30B 单卡，2488 → 1753 ms） |
| 最干净的单点 | OPT-30B/256：343.0 → 227.6 ms，1.51× |
| α 的取值 | OPT/BLOOM 0.5、GLM 0.75、LLaMA 0.8、Llama-2-70B 0.9；甜点区间 0.4~0.6 |

**结论**：**W8A8 是量化族里唯一能直接用满 A800 / 4090 INT8 张量核的一支**，与被排除的 W4A8 / FP4 路线形成对照——不是"精度高一点低一点"的差别，是"有没有对应硬件路径"的差别。

可迁移的是变换本身：离线完成、运行时零开销、免重训。代价是校准数据必须有代表性——这一点对自动驾驶场景是实打实的约束，线上语料与公开校准集必然不同分布。

> 引用纪律：1.56× 只对 FasterTransformer 基线、且限 A100；论文只测延迟，没有报吞吐。报告里只能写"约 2× 显存、1.2~1.5× 延迟"这个量级。

## 五、GPTQ：用二阶信息补偿误差

**出处**：ICLR 2023，arXiv:2210.17323 | **开源**：`IST-DASLab/gptq` | **平台**：A100 80GB 单卡量化，端到端对照 5~8 卡 FP16

**问题**：已有的重构式方法（OBQ）对每个权重求解一次最优量化，复杂度随参数量爆炸，十亿参数级就不可行。而 round-to-nearest 又快又糙——OPT-175B 上 3 bit 的困惑度直接到 $7.3 \times 10^3$。

**方法**：

1. **逐层重构**：一层一层量化，每层只最小化该层输出的重建误差，不碰全模型。
2. **固定列序 + Hessian 补偿**：按固定顺序逐列量化，用 $H^{-1}$ 的二阶信息把当前列的量化误差摊到尚未量化的列上。
3. **惰性批量更新**：每 128 列才更新一次后续列的误差，把复杂度摊薄。
4. **Cholesky 重排**：改造 Hessian 的 Cholesky 分解，让数值在 175B 规模下稳定。
5. **共用列序的前提**：同一层所有行按同一列序处理，这是能批量化的关键假设。

**结果**：

| 项 | 数字 |
|---|---|
| 量化耗时 | OPT-175B **4.2 h**、BLOOM-176B 3.8 h（单卡 A100 80GB） |
| OPT-175B 精度 | FP16 8.34 / 4-bit **8.37** / 3-bit 8.68 |
| RTN 对照 | OPT-175B 4-bit 10.54、3-bit $7.3 \times 10^3$ |
| 端到端 | A100：3-bit 单卡 71 ms 对 FP16 5 卡 230 ms，**3.24×** |
| 单卡容纳 | 3-bit OPT-175B 约 63 GB 权重 + 9 GB KV，5 卡 → 1 卡 |
| 解压开销 | A100 低于 1.5 ms |

**结论**：**3.24× 是"5 卡 FP16 → 1 卡 3-bit"的容量换算，不是单卡加速。** 这个口径必须说清楚，否则等于把换卡的钱算进算法收益里。A800 与 A100 同 sm80、同约 2.0 TB/s，机制上可平移（论文未测）；4090 带宽 1.0 TB/s、显存 24 GB，只能跑到 7B/13B，而这一档论文完全没测，写预期时必须标为假设。

第二个限制：**论文随代码只发布了 3-bit kernel，4-bit 只有精度结果。** 要写"W4A16 加速"，4-bit 的系统实现要另找来源（AutoGPTQ / GPTQModel / Marlin），不能归到本文名下。

## 六、AWQ：本课题最该跑的一个

**出处**：MLSys 2024（Best Paper），arXiv:2306.00978 | **开源**：`mit-han-lab/llm-awq`，**已并入 vLLM / TensorRT-LLM / HuggingFace** | **平台**：桌面 GPU（**含 RTX 4090**）与移动 GPU

**问题**：两个叠在一起。一是量化误差高度集中：少数显著通道决定了几乎全部退化，均匀量化在它们身上浪费位宽。二是部署成本：GPTQ 类重构方法要 192 条校准数据、要跑逐层重构，对"拿来就能用"的场景太重。

**方法**：

1. **显著性的判据是激活幅值，不是权重范数**。物理依据：权重的重要性由它乘上的激活决定，权重本身大不等于重要。显著通道占比约 0.1%~1%。
2. **per-channel 缩放**：对显著通道乘一个 $s > 1$ 的系数再量化，量化后除回去。等价于把误差从显著通道挪到不显著的通道上，而后者本来就承受得起。
3. **缩放系数的搜索**：$s = s_X^{\alpha}$，α 一维搜索——与 SmoothQuant 的形式同源，但作用对象是权重通道而非激活通道。
4. **校准只要 16 条**，且对跨分布数据的鲁棒性明显优于 GPTQ。
5. **系统侧**：TinyChat 做 kernel 融合与权重打包——加速数字的另一个来源，见下面的口径拆分。

**结果**：

| 项 | 数字 |
|---|---|
| OPT-6.7B INT3-g128 | RTN 23.54 → AWQ **11.39** |
| Llama-2-7B INT4-g128 | FP16 5.47 → AWQ 5.60 |
| **4090 加速比** | 平均 **3.2~3.3×**，基线 HuggingFace FP16 |
| 4090 roofline | 165 TFLOPS / 1 TB/s，拐点 165；W4A16 后算术强度约 4，算力上限约 4 TFLOPS |
| 访存失衡 | 权重/激活访存倍数：Attention 79×、FFN 1700× |
| 生成 vs 预填 | Llama-2-7B 在 4090：生成 20 token 310 ms，上下文 200 token 仅 10 ms，差约 31× |
| 校准成本 | AWQ 16 条 对 GPTQ 192 条；跨分布 PPL 增量 0.5~0.6 对 2.3~4.9 |

**结论**：**加速比必须拆成两段看。** Llama-2-7B 在 4090 上从 52 到 62 tokens/s 这一段来自 FP16 kernel 融合，再乘 3.1 才来自 4-bit kernel。把整体 3.9× 说成"量化收益"站不住，答辩时会被追着问。

**收益只在 batch=1 的 decode 阶段成立。** AWQ 省的是每步读权重的时间，batch 一大，瓶颈从带宽转向算力，收益收窄。这与第一篇 A800 实测的"batch 越大、吞吐增益衰减"是同一件事的两面。

显著性判据是全文最可迁移的结论，与硬件无关。配套的 α 一维搜索和 16 条校准集，对自动驾驶场景（校准语料与线上分布必然不同）直接可用。

## 七、四条路线对照：数字不可并列

| 方法 | 量化对象 | 位宽 | 校准 | 硬件依赖 | 运行时形态 |
|---|---|---|---|---|---|
| LLM.int8() | 权重 + 激活 + 离群维混合 | W8A8 + FP16 分支 | 不需要（在线统计） | INT8 张量核 | 混合精度分解，多一条 FP16 通路 |
| SmoothQuant | 权重 + 激活 | W8A8 | 512 句 | INT8 张量核 | 尺度折进前一层，零开销 |
| GPTQ | 权重 | W4/W3（发布 3-bit kernel） | 128~192 条 | 反量化路径 | 逐层重构，离线 4 h 级 |
| AWQ | 权重 | W4A16 | **16 条** | 反量化路径 + 自研 kernel | 逐通道缩放，离线分钟级 |

关键数字对照（口径已拆开）：

| 方法 | 精度代价 | 压缩比 / 显存 | 延迟或吞吐 | 平台与基线 |
|---|---|---|---|---|
| LLM.int8() | 13B PPL 与 FP32 相等 | BLOOM-176B 1.96× | 端到端 10.44 对 9.94 ms/token（**更慢**） | 8×A100，bf16 基线 |
| SmoothQuant | OPT-175B 七任务 66.9 → 66.8 | 1.96×（PyTorch 侧） | INT8 GEMM 1.56×；解码 1.42× | A100，FT-FP16 基线 |
| GPTQ | OPT-175B 8.34 → 8.37（4-bit） | 约 5.3×（3-bit） | 3.24×（**5 卡 → 1 卡的容量换算**） | A100，多卡 FP16 基线 |
| AWQ | Llama-2-7B 5.47 → 5.60 | 约 4×（W4） | 平均 3.2~3.3× | 4090，HF FP16 基线（**含 kernel 融合**） |

**四个数字不可并列**：一个比的是 ms/token，一个比的是单层 GEMM，一个比的是多卡换单卡，一个含 kernel 融合。

文献里打架的几处与判定：

| 冲突 | A 说 | B 说 | 怎么判 |
|---|---|---|---|
| W4A16 的加速来源 | AWQ：3.2~3.3× 是量化收益 | 同一篇正文：52 → 62 来自 kernel 融合 | 拆开报，只把乘 3.1 那段算量化 |
| 多卡收益 | GPTQ：3.24× 加速 | 实为 5 卡换 1 卡 | 写成"容量换算"，不写成算法加速 |
| W8A8 能不能用 | LLM.int8()：端到端反而慢 | SmoothQuant：1.42~1.56× | 前者含混合精度开销，后者是干净 GEMM；写"取决于 kernel 与 batch" |
| 4-bit 有没有 kernel | GPTQ 论文给出 4-bit 精度 | 仓库只发 3-bit kernel | 4-bit 系统实现另找来源，不挂在 GPTQ 名下 |

四条线共同的前提：都是 post-training、都不改训练流程；都假设权重分布在校准集与线上数据之间不漂移太多；都只在特定负载下成立——AWQ 只对 batch=1 的 decode 有效，SmoothQuant 的算力收益主要体现在 prefill 与大 batch，GPTQ 的收益主要来自"少占卡"；**都不改变每步的 KV 读取量**——KV 侧的收益必须另找 KV 压缩那批方法。

## 八、落到实验：两步走

按落地成本排序：

1. **AWQ（W4A16）先跑**——vLLM 内置，用官方量化权重，不需要自己跑量化流程。它直接检验主线：权重位宽约减半，短上下文解码吞吐应明显上升；**若没有上升，本身也是结论**。
2. **KV cache FP8 随后**——vLLM 的 `kv_cache_dtype` 参数，一行配置。预期收益小（KV 占比 4%~9.5%），正好把"短上下文 KV 压缩无效"从推论变成实测。

暂不做：KIVI（要编 kernel、改注意力路径）、SnapKV（要接进调度）——留到中期。

## 九、二维判据：位宽 × KV 占比

第一篇给出的是一维判据（KV 读取占比决定该做什么）。量化补上了**第二条轴**：权重位宽决定每步读取量的下限。两条合一才完整：

| KV 占比 | 该做什么 | 依据 |
|---|---|---|
| 低于 10%（短上下文、小 batch） | 权重侧量化 | 权重占读取量 90% 以上；KV 压缩收益上限只有个位数百分比 |
| 10%~60% | 两者都做，先测交叉点 | 实测的中段，尚无文献数据 |
| 高于 65%（长上下文、大 batch） | KV 压缩 / 驱逐 | KV 读取已占三分之二，压 KV 的空间最大 |

这张表的横轴是 KV 占比，纵轴是相对加速比，两类方法各一条曲线，**交叉点就是整个课题要找的结论**——它把四批文献的方法适用区间统一到一根轴上。

## 十、小结

1. 四篇量化论文是一条叙事链：发现离群值 → 迁移难度 → 二阶补偿 → 激活感知。共同物理基础是"量化误差高度集中"。
2. LLM.int8() 是显存路线不是速度路线，端到端反而更慢；但它的维度阈值效应给"硬件感知"留出了自测区间。
3. 能压到多低取决于模型结构与硬件通路：W4A16 与 W8A8 在 A800 / 4090 可用，W4A8 / KV4 / FP4 不可用。
4. 四个头条数字口径各不相同，不可并列；GPTQ 的 3.24× 是容量换算，AWQ 的 3.2~3.3× 含 kernel 融合。
5. 实验顺序：AWQ 先跑（vLLM 内置、官方权重、半天到一天），KV FP8 随后（一行配置、预期小收益）。
