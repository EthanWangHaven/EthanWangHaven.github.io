前两篇处理的是"每次读多少数据"。这一篇换一条轴：**每次读取能产出多少 token**。

瓶颈在这里：decode 每一步都要把整个模型权重读一遍，而这一步只产出一个 token。权重读取量是固定的、无法靠"少读"解决——只能让这次读取多产出几个。



## 一、投机解码的基本框架

**Draft-then-Verify**：每一步先用一个便宜的草稿器猜出 $\gamma$ 个未来 token，再让目标模型**一次前向**并行验证这 $\gamma$ 个候选，接受最长的正确前缀。

```
常规解码      前向 → 1 token    前向 → 1 token    前向 → 1 token   （3 次前向 = 3 token）
投机解码      草稿 → γ 候选
              目标模型一次前向验证 γ 个 → 接受 k 个                       （1 次前向 = k+1 token）
```

代价结构因此变成：**每步省下 (k) 次目标模型前向，但多了 1 次草稿开销 + 1 次验证开销**。加速比来自两者的比值，而 `k`（接受长度）取决于草稿器的准确率。

## 二、为什么它原理上可以无损

走**投机采样**（speculative sampling）判据时，输出分布与目标模型严格一致。核心公式（Leviathan 等 2023）：

$$
\beta = \min\left(1, \frac{p(x)}{q(x)}\right), \qquad
p'(x) = \frac{\max(0,\ p(x)-q(x))}{\sum_{x}\max(0,\ p(x)-q(x))}
$$

即对草稿 token $x$ 以概率 $\beta$ 接受；一旦拒绝，就在残差分布 $p'$ 上重新采样。理论上可以证明这样采出来的 token 服从 $p$。

**但"无损"有三处必须限定，不能笼统写成"输出分布完全一致"**：

1. **FP16 下不严格成立**。投机解码综述 §D.3 明写只有 FP32 下输出才与自回归严格相同，FP16 下浮点误差会累积；而该综述表 5、表 6 的实测全部是 FP16。
2. **Medusa 的 typical acceptance 偏离分布一致**。论文自陈它偏离了"输出必须精确对应语言模型分布"，靠 ϵ、δ、温度三个量调，是拿一致性换加速率；只有走拒绝采样时才保持。
3. **Lookahead 的证明有前提**。分布保持的证明针对采样验证算法，且前提是 n-gram 生成端强制贪心；它的贪心路径在 FP16 下与 HuggingFace greedy search 并不逐字一致，论文归因于数值精度（附录 E）。

## 三、四条路线：要不要额外模型、要不要训练

| 路线 | 代表 | 需要额外模型 | 需要训练 | 占额外显存 |
|---|---|---|---|---|
| 独立 draft model | （传统投机采样） | 要，一个独立小模型 | 要预训练小模型 | 占 |
| 自投机：多解码头 | Medusa | 不要外部模型 | 训 K 个解码头（MEDUSA-2 还要动主干） | 占（解码头 + 候选树） |
| 自投机：特征层草稿 | EAGLE、EAGLE-2 | 不要外部模型 | 按 target 各训一份（0.24B~0.99B） | 占（草稿权重常驻） |
| 自投机：跳层 | LayerSkip、Draft & Verify | 不要 | LayerSkip 要自训权重；Draft & Verify 免训练（需离线选层） | 不占（共用一份权重） |
| n-gram 检索 | Lookahead | 不要 | **完全免训练** | 不新增权重 |
| 树结构并行 | Medusa、EAGLE、EAGLE-2 | — | — | — |

读法有三条：**免训练的只有 Lookahead 与 Draft & Verify；不额外占显存的只有 LayerSkip 与 Draft & Verify**（代价都压在别处——一个压训练，一个压离线搜索）；代码最稳的是 EAGLE 系列与 Medusa（后者已进 vLLM / TRT-LLM）。

## 四、Medusa：在最后一层挂 K 个解码头

**出处**：ICML 2024，arXiv:2401.10774v3 | **开源**：`FasterDecoding/Medusa`，已并入 vLLM / TRT-LLM | **平台**：训练单张 A100 PCIe；主实验卡型原文未印

**问题**：独立 draft 模型既要够小又要够准，往往需要单独预训练（转引 Miao 等 2023 的报告：275 NVIDIA A100 GPU 小时）。且独立预训练会在 draft 与 target 之间引入分布偏移，使 target 拒绝 draft 的续写。

**方法**：取消 draft model，把 K 个轻量解码头直接挂在主干最后一层隐状态上。

1. **解码头结构**。主干在位置 t 的末层隐状态为 $h_t$，第 k 个头预测未来第 $(t+k+1)$ 个位置的 token：

$$
p_t^{(k)} = \text{softmax}\left(W_2^{(k)} \cdot \text{SiLU}(W_1^{(k)} h_t) + h_t\right), \quad
W_2^{(k)} \in \mathbb{R}^{d \times V},\ W_1^{(k)} \in \mathbb{R}^{d \times d}
$$

初始化取 $W_2^{(k)}$ 等于原语言模型头、$W_1^{(k)}$ 置零，使解码头初始预测与原模型一致。因为头长在主干的表示之上，头与主干的分布天然对齐，分布偏移问题同时被消掉。

2. **MEDUSA-1：冻结主干，只训头**。损失为各头交叉熵加权和，$\lambda_k = 0.8^k$。因为主干只提供隐状态，可以用量化后的主干省显存。

3. **MEDUSA-2：解码头与主干联合微调**。$\mathcal{L}_{\text{MEDUSA-2}} = \mathcal{L}_{\text{LM}} + \lambda_0 \mathcal{L}_{\text{MEDUSA-1}}$，配套三条措施：组合损失、差分学习率（头取主干的 4 倍）、头部预热两阶段训练。

4. **tree attention：一次前向验证整棵树**。第 k 个头取 top-$s_k$ 个预测，候选由各头 top-$s_k$ 的**笛卡尔积**构成。注意力掩码只允许 token 关注其前驱，位置编码下标按树结构调整，于是**多个候选可以并行处理而不扩大 batch size**。

5. **接受判据两种**。拒绝采样保证分布一致但效率随温度下降；**typical acceptance** 逐位置判定：

$$
p_{\text{original}}(x_{n+k} \mid x_1 \dots x_{n+k-1}) > \min\left(\epsilon,\ \delta \cdot \exp(-H(p_{\text{original}}(\cdot \mid x_1 \dots x_{n+k-1})))\right)
$$

6. **优化树构造（离线）**。用标定数据集统计每个头第 i 个 top 预测的准确率，在"各头独立"假设下估候选序列的接受概率，从当前树出发贪心接入准确率最高的相邻节点，直到节点数达到预算。

**实测加速比**（wall-time，相对默认 HuggingFace 实现，batch size 1）：

| 模型 | MEDUSA-1 | MEDUSA-2 |
|---|---|---|
| Vicuna-7B | 2.18× | **2.83×** |
| Vicuna-13B | 2.33× | **2.83×** |
| Vicuna-33B | — | 2.35× |
| Zephyr-7B | — | 2.66× |

消融贡献分解（Table 3）：只用头、不加 tree attention **~1.5×** → 加 tree attention **~1.9×** → 用优化树配置 **~2.2×** → 用 MEDUSA-2 训练头 **~2.8×**。

**代价**：

- **解码头是额外参数**（每头两个矩阵，但论文未给绝对值）。
- **树越大显存与算力开销越大**。树规模直接进入注意力与线性层的空间复杂度。论文主实验是 **batch size 1**，且未在消费级卡上跑。
- **收益随树规模递减**。64 节点的稀疏树优于 256 节点的稠密树；加速率按对数增长，树超过约 64 个候选后加速比下降。
- **typical acceptance 不再保证分布一致**。

> 口径：所有加速比都是 **wall-time 加速比** = Acceleration rate / Overhead，相对默认 HuggingFace 实现、batch size 1。附录 G 的"44× FLOP/s 与 41× 算术强度"是**单个算子在 roofline 上的提升**，不是端到端加速比，当加速比引用是量级错误。
>
> 两个版本必须分清：MEDUSA-1 冻结主干只训头（7B 2.18×、13B 2.33×），MEDUSA-2 联合微调（7B/13B 2.83×、33B 2.35×）。写"Medusa 2.3~2.8×"必须交代是哪一版。

## 五、EAGLE：把草稿改到特征层

**出处**：arXiv:2401.15077v3 | **开源**：`SafeAILab/EAGLE` | **平台**：RTX 3090 24GB 单卡、4×A100 40G；主实验卡型未印

**问题**：7B 这一档没有可用的草稿模型——同系列没有更小的，7B 作 13B 的草稿则自身开销过大（实测 13B 上**没有任何加速**，33B 1.12×，70B 1.88×）。

**两条观察（全族理论支点所在）**：

- **观察一**：特征层自回归比 token 层更直接。token 序列是自然语言的简单变换，特征序列"更规整"；先在特征层自回归、再用 target 的 LM head 导 token，优于直接预测 token。单变量消融给出 token 层 1.5× 对特征层 1.9×。
- **观察二**：特征是高维连续量，下一个特征取决于采样结果，因此仅凭当前特征无法确定下一个特征。**解法**是把"提前一个时间步"的 token 作为已知条件喂进去。消融上加速比由 1.9× 升到 2.8×。

**草稿模块结构**：三个模块——Embedding 层、LM Head、Autoregression Head。前两个**直接采用 target 的参数，不参与训练**。可训练部分只有一个 transformer decoder 层，按 target 各训一份：7B 0.24B、13B 0.37B、33B 0.56B、70B 0.99B 参数。

**训练**：预测下一特征是回归任务，用 Smooth L1 损失；再并行加一路分类损失（`w_cls = 0.1`，理由是分类损失数值上大一个数量级）。数据用固定 ShareGPT，训练时给特征加 $U(-0.1, 0.1)$ 噪声以缓解误差累积。

**关键数字**：

- MT-bench 上整体 **2.1×~3.8×**；LLaMA2-Chat 13B 在 T=0 时 3.01×~3.76×，T=1 时降到 2.66×~2.89×。
- 代码生成（HumanEval）加速最好（Llama2-Chat 13B 3.76×），原因是代码里固定模板多、草稿好出。
- 每轮 target 前向产出 **3.2~4.5 个 token**（vanilla 只有 1 个）。
- Mixtral 8x7B 只有 **1.50×**——MoE 每 token 只读两个专家的权重，验证多个 token 时可能要读多于两个专家。
- 与 gpt-fast 权重量化联合（RTX 3090、LLaMA2-Chat 7B）：gpt-fast FP16 55.1 → int4 106.9；EAGLE+gpt-fast FP16 100.2 → int4 **160.4** token/s。

**代价**：

- **不是免训练方法**，草稿按 target 各训一份。
- **显存紧时反而有害**：草稿模块本身占显存，Vicuna 7B 在 24GB 的 3090 上最大 batch 由 8 降到 **7**；70B 在 160GB 上由 5 降到 4。这一条对 24GB 的 4090 是硬约束。
- **批大小越大加速比越低**：bs=1→4 时 Vicuna 7B 从 2.90× 降到 2.76×、LLaMA2-Chat 70B 从 3.01× 降到 2.40×。原因是批量已经把 GPU 算力用掉，而投机采样正是靠闲置算力换加速。
- **MoE target 上收益缩水**；**非贪心下加速比下降**。

> 三个口径先分清：墙钟延迟加速比、吞吐提升（约 2×）、平均接受长度 τ（3.2~4.5 tokens/前向）。**τ 不等于加速比**——树式方案 τ 涨 0.6~0.8 而加速比只涨 0.3~0.5，正是两者不等价的证据。
>
> "特征层不确定性低于 token 层"这个支点缺直接证据：论文给的是概念论述 + 一组单变量消融，**没有熵或方差的测量，也没有形式化证明**。引用时应写成"论文以消融支持"。

## 六、EAGLE-2：把静态树改成动态树

**出处**：arXiv:2406.16858v2 | **开源**：与 EAGLE 同仓库（权重与配置分两套） | **平台**：论文未印 GPU 型号与卡数

**问题**：EAGLE-1 的草稿树形状是**静态**的，所有上下文共用一套形状。EAGLE-2 用两个实验反驳"接受率只取决于位置"这条假设：同一位置的接受率方差很大，说明它还依赖上下文；而直接算接受率要跑原模型前向，与投机采样的初衷冲突。

关键发现：EAGLE 的草稿模型**校准良好**——它给出的置信度能小幅误差地逼近接受率（置信度低于 0.05 的草稿 token 接受率约 0.04；高于 0.95 的约 0.98）。

**方法**：不改草稿模型的训练与推理，也不改验证阶段，只动两处：

1. **定义节点的值**：从根到该节点路径上所有节点接受率的连乘，实践里用草稿置信度代替接受率。理由是一个 token 最终被接受的前提是它的全部前缀都被接受。

$$
V_i = \prod_{t_j \in \text{Path}(\text{root}, t_i)} p_j \approx \prod_{t_j \in \text{Path}(\text{root}, t_i)} c_j
$$

2. **扩展**：取当前层值最高的 top-k 个节点送进草稿模型，构成下一层。
3. **重排**：值在 0 与 1 之间，越深的节点值越低，因此没被扩展的浅层节点可能比已扩展的深层节点更值钱。于是对**全部**草稿 token 按值重排，取全局 top-m；值相同时优先取更浅节点，保证选出的 token 仍构成连通的树。
4. 拉平成一维序列交给验证阶段，按树结构改写注意力掩码。

**关键数字**：摘要口径三个模型系列六个任务上加速 **3.05×~4.26×**，比 EAGLE-1 快 20%~40%。Vicuna 13B、T=0 逐任务：MT-bench 4.26×、HumanEval 4.96×、GSM8K 4.22×、Alpaca 4.25×、CNN/DM 3.40×、Natural Questions 3.13×，六任务平均 **4.04×**。

> **"动态"不等于"按上下文长度伸缩"**。动态指的是按节点值在同一上下文内选择性扩展与重排；树深度与草稿 token 上限仍是逐模型规模设定的常数（7B/8B 60、13B 50、70B 48，深度 6）。
>
> 论文未报任何显存占用，也未在 24GB 级消费卡上实验。接 4090 时应先自行测"原模型权重 + 草稿权重 + 树掩码 KV"这块显存，再谈加速比。

## 七、LayerSkip：唯一不额外占显存的路线

**出处**：arXiv:2404.16710v4 | **开源**：`facebookresearch/LayerSkip`（需自训权重） | **平台**：训练 8~64×A100；推理 H100 / A100

**动机探测**（论文自带测量）：Llama1 7B 上平均一个 token 需要 **23.45 / 32 层**，因此**即使有一个零计算开销的完美预测器，也只能省下 26% 的计算**。前层预测基本只是"上一个 token 投影到 embedding 权重上"的结果。所以不能只改推理去挑层，必须改训练让模型少依赖后层。

**方法**：

1. **层丢弃（layer dropout）**。训练时对每层随机整层跳过：

$$
x_{l+1,t} = x_{l,t} + M(p_{l,t}) f_l(x_{l,t})
$$

丢率按层与按步分解 $p_{l,t} = S(t) D(l) p_{max}$，逐层缩放函数从第 0 层 0.0 升到第 $L-1$ 层 1.0——**前层低丢率、后层高丢率**，目的是让模型少依赖后层。

2. **早退损失**。把低层输出也接到**共享** LM head 上（不额外加头），直接监督低层做语言建模：

$$
J(X,Y,t) = \sum_{l=0}^{L-1} \tilde e(t,l) J_{CE}(g(x_{l+1}), Y)
$$

3. **早退损失课程**：对所有层每步都开早退会拖慢训练并降低末层精度，因此引入旋转课程或渐进课程。
4. **自投机解码两步**：用同一个模型的前 E 层自回归生成 d 个草稿 token（self-drafting）；用剩下的 L−E 层一次前向并行验证（self-verification）。
5. **KVQ 缓存复用**：草稿与验证共用前 E 层的 KV cache，只需再保存出口层的 query 向量。因此**只维护一份 KV cache**。

**关键数字**（各配置实测，相对未施加 LayerSkip 的自回归基线，按每 token 平均时间）：

| 配置 | 卡 | 加速比 |
|---|---|---|
| 继续预训练 Llama2 7B / 13B，CNN-DM | H100 | 1.86× / 1.81× |
| 继续预训练 Llama2 7B，HumanEval | H100 | 1.83× |
| 从头预训练 Llama2 7B，CNN/DM | H100 | **2.16×** |
| 代码微调 Llama1 7B，HumanEval | A100 | **1.82×** |
| 任务微调 TOPv2 | H100 | **2.0×** |

**代价**：

- **不省常驻显存，只省"第二份模型"**。验证阶段要用全部 L 层，所以完整权重与至少一份 KV cache 始终在显存里。相比标准双模型方案省掉的是**额外的 draft 权重、它的 KV cache，以及两套缓存的维护复杂度**。论文**未给显存实测数字**。
- **收益完全由早退层精度决定**。早退单跑时质量掉得很厉害（CNN/DM ROUGE-2 从 0.079 掉到 0.012）——加速比的代价全部压在自验证能拉回多少。
- **需要自训一份权重**，且 $p_{max}$、$e_{scale}$、$R$、课程类型都要调。

> 三个头条数不是一套设置：2.16× 是"从头预训练 + CNN/DM + H100"，1.82× 是"代码微调 + HumanEval + A100"，2.0× 是"任务微调 TOPv2 + H100"。不能合成一句"三种任务都有约 2× 加速"。
>
> 论文内部有前后不一致：摘要写最高 2.16×，结论节写"最高 1.86×"。引用以具体表格为准。

## 八、Lookahead：完全免训练的 n-gram 路线

**出处**：arXiv:2402.02057（Lookahead Decoding） | **开源**：`hao-ai-lab/LookaheadDecoding` | **平台**：A100 80GB / 8×A100 40GB，另有 3090 对照

**思路**：把自回归生成的串行依赖本身拆掉，换成 **Jacobi 迭代并行解码**——用 n-gram 池记住历史上出现过的 token 序列，从池子里直接取候选，多步同时推进，最后选最长一致的前缀。完全免训练、不需要额外的草稿模型。

**代价**：8 卡 lookahead parallelism 是强扩展口径；n-gram 池单独占显存（论文只定性说 "huge memory"，无实测值）。

> 常被引用的"4×"是 8 卡强扩展口径，不是单卡端到端数字。

## 九、"正交"不等于"收益可以相加"

三条思想轴（少读 KV、少读权重、多出 token）理论上可以叠加，但本批自带了两组关键证据与一个反例：

**正例一**：EAGLE + gpt-fast 权重量化（RTX 3090、LLaMA2-Chat 7B、T=0，token/s）

| 配置 | FP16 | int4 |
|---|---|---|
| gpt-fast | 55.1 | 106.9 |
| EAGLE + gpt-fast | 100.2 | **160.4** |

**正例二**：Draft & Verify 把量化叠在自己方法之上（LLaMA-2-13B + CNN/DM）：bf16 1.53×、fp8 1.61×、fp4 1.36×、nf4 1.35×。

**反例**：同一张表里，叠加稀疏化后本方法的**相对加速比反而下降**（dense 1.57× → 4:8 1.47×）。论文的解释是基座模型本身也被加速了。

**结论：可叠加不等于收益相加。** 组合实验的收益必须实测，这正是我这批实验里打算做的一件事。

## 十、本批共同的边界

**8 篇全部作用于 decode 阶段，prefill 不受益。** 自回归串行这条瓶颈只存在于 decode。这与 KV 压缩那一批相反——那批有 DuoAttention 与 ShadowKV 能改善 prefill，本批没有对应物。

另一个共同限制是 **batch 越大收益越低**：投机采样靠"批量没用完的闲置算力"换加速，batch 一大，算力被吃满，收益就消失。EAGLE 在 24GB 卡上还会因为草稿权重挤占显存而**压低最大 batch**（8 → 7）。这两条叠起来，意味着投机解码**只适合单请求、低并发的延迟敏感场景**——这恰好是 A800 上 batch=1 时 94.8 tok/s 的那个场景。

## 十一、小结

1. 投机解码换的是"一次权重读取多产出几个 token"这条轴，与 KV 压缩、权重量化正交。
2. 无损只在 FP32 + 拒绝采样 + 贪心强制这几个前提下成立；Medusa 的 typical acceptance 是拿一致性换加速率。
3. 落地成本差异极大：Lookahead 免训练、Draft & Verify 免训练但需离线选层、LayerSkip 要自训权重、EAGLE 按 target 各训一份草稿、Medusa 只训头（最简单）。
4. 加速比区间（各自口径）：Medusa 2.3~2.8×、EAGLE 2.1~3.8×、EAGLE-2 3.05~4.26×、LayerSkip 1.34~2.16×。
5. **失效条件统一**：大 batch 下收益衰减、prefill 不受益、显存紧时反而有害。
6. 与其它方法叠加有收益但不保证相加，需要实测。
