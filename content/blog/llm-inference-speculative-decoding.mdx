前两篇处理的是每次读取的数据量（KV cache 与权重位宽）。这篇对应第三条瓶颈：自回归串行。decode 每步读取全部权重只产出一个 token，权重读取量固定、无法减少，改进方向是让一次读取产出多个 token。

## 一、框架与无损条件

投机解码采用 draft-then-verify 框架：每步先用低开销的草稿器生成若干候选 token，再由目标模型一次前向并行验证，接受最长的正确前缀。

```
常规解码    每次前向产出 1 token
投机解码    草稿生成候选 → 目标模型一次前向验证 → 接受 k 个
```

每步节省 k 次目标模型前向，增加一次草稿开销与一次验证开销，加速比取决于两者的比值。接受长度 k 由草稿器准确率决定，各方法的差异集中在草稿器的构造上。

走投机采样判据时，输出分布与目标模型一致（Leviathan 等 2023）：对草稿 token 以 $\min(1, p(x)/q(x))$ 的概率接受，拒绝时在残差分布 $p'(x) = \max(0, p(x)-q(x)) / \sum_x \max(0, p(x)-q(x))$ 上重新采样，采样结果服从 p。

"无损"有三处限定。FP32 下输出才与自回归严格一致，投机解码综述 §D.3 明确 FP16 下浮点误差会累积，而该综述的实测全部在 FP16 下进行。Medusa 的 typical acceptance 论文自陈偏离了"输出精确对应原模型分布"，以分布一致性换取加速率，只有拒绝采样路径保持一致。Lookahead 的分布保持证明有前提（采样验证算法、生成端强制贪心），其贪心路径在 FP16 下与 HuggingFace greedy search 不逐字一致，论文归因于数值精度。

## 二、Medusa：多解码头与 tree attention

独立的 draft model 需要单独预训练，且要同时满足足够小与足够准。Medusa 转引的报告为 275 个 A100 GPU 小时；独立预训练还会在 draft 与 target 之间引入分布偏移，导致 target 拒绝 draft 的续写。Medusa（ICML 2024）不使用独立的 draft model：在主干最后一层隐状态上挂 K 个轻量解码头，第 k 个头预测未来第 k+1 个位置的 token：

$$
p_t^{(k)} = \text{softmax}\left(W_2^{(k)} \cdot \text{SiLU}(W_1^{(k)} h_t) + h_t\right), \quad
W_2^{(k)} \in \mathbb{R}^{d \times V},\ W_1^{(k)} \in \mathbb{R}^{d \times d}
$$

候选由各头 Top-k 的笛卡尔积构成，用 tree attention 在一次前向内并行验证整棵候选树。解码头建立在主干的表示之上，头与主干的分布对齐，分布偏移问题随之消除。

训练分两档，数字需分开引用：MEDUSA-1 冻结主干只训解码头，7B 上 2.18×、13B 上 2.33×；MEDUSA-2 联合微调主干，7B / 13B 达 2.83×，需要组合损失、差分学习率（解码头取主干的 4 倍）与头部预热。消融分解：只加解码头约 1.5×，加 tree attention 约 1.9×，优化树配置约 2.2×，联合微调约 2.8×。

两处口径需要区分。全部加速比是 batch size 1 的 wall-time、相对默认 HuggingFace 实现；附录 G 的"44× FLOP/s"是注意力矩阵乘单个算子在 roofline 上的提升，不能作为端到端加速比引用。树的规模存在收益上限：64 节点的稀疏树优于 256 节点的稠密树，加速率按对数增长，树过大后线性层与注意力矩阵乘的开销使该步进入计算受限区。

## 三、EAGLE：特征层草稿

7B 档没有可用的 draft model：同系列没有更小的模型，7B 作 13B 的草稿自身开销过大，EAGLE 实测 13B 上无加速、33B 仅 1.12×。EAGLE 将草稿生成从 token 层移到特征层，理由是 token 序列只是自然语言的简单变换，特征序列更规整；特征是高维连续量，下一特征取决于采样结果，因此将提前一个时间步的 token 作为已知条件输入。单变量消融：token 层 1.5× → 特征层 1.9× → 加入提前 token 2.8×。

结构上只训练一个 transformer decoder 层（7B 对应 0.24B 参数），Embedding 与 LM Head 复用 target 的参数、不参与训练。训练损失为 Smooth L1 加一路分类损失（权重 0.1，分类损失数值上大一个数量级），训练时对特征加 $U(-0.1, 0.1)$ 噪声以缓解误差累积。

MT-bench 上整体 2.1×~3.8×，代码生成最高（HumanEval 3.76×），原因是代码的固定模板多、草稿命中率高。两点需要注明。其一，"特征层不确定性低于 token 层"这一支点缺直接证据，论文给的是概念论述与一组单变量消融，没有熵或方差的测量，引用时写"论文以消融支持"。其二，草稿权重常驻显存，Vicuna 7B 在 24GB 的 3090 上最大 batch 由 8 降为 7；论文未在 4090 上测试。

另有一组数据后文会引用：EAGLE 与 gpt-fast 的 int4 权重量化联合（3090、LLaMA2-Chat 7B）达到 160.4 token/s，单独 gpt-fast int4 为 106.9。

## 四、EAGLE-2：动态草稿树

EAGLE-1 的草稿树是静态的，所有上下文共用一套形状。EAGLE-2 观察到 EAGLE 的草稿模型校准良好：置信度与接受率的误差较小，置信度低于 0.05 的草稿 token 接受率约 0.04，高于 0.95 的约 0.98。于是以置信度作为接受率的代理，动态调整树形：节点值定义为路径上接受率的连乘（一个 token 被接受的前提是全部前缀被接受），扩展时取当前层值最高的 top-k 个节点，重排时对全部草稿 token 按值取全局 top-m。不改训练、不改验证，六个任务平均加速 4.04×（Vicuna 13B，T=0），较 EAGLE-1 提升 20%~40%。

"动态"的含义需要澄清：指同一上下文内按节点值选择性扩展与重排；树深度与草稿 token 上限仍是逐模型规模手工设定的常数。论文未印 GPU 型号，也未报显存占用，接 4090 前需要自行测量显存。

## 五、LayerSkip 与 Lookahead

LayerSkip 是八篇中唯一不增加常驻显存的。动机来自逐层探测：Llama1 7B 平均一个 token 需要 23.45 / 32 层，零开销完美预测器的收益上限也只有 26%，因此只改推理挑层不可行，需要在训练侧让模型少依赖后层。配方为层丢弃（前层低丢率、后层高丢率）与早退损失（低层输出直接接共享 LM head）；推理时前 E 层自回归生成草稿，后 L−E 层一次前向验证，KV cache 只维护一份。

代价集中在训练侧：需要自行微调一份权重，超参包括丢率、早退权重与课程类型。收益由早退层精度决定：早退单独使用时质量下降明显（CNN/DM 的 ROUGE-2 从 0.079 降至 0.012），依靠自验证恢复。加速比 1.34×~2.16×。摘要的三个头条数来自不同训练配置与不同卡（2.16× 为从头预训练 + CNN/DM + H100，1.82× 为代码微调 + HumanEval + A100，2.0× 为任务微调 TOPv2 + H100），不能合并表述。论文内部也有不一致：摘要写最高 2.16×，结论节写最高 1.86×，引用以表格为准。

Lookahead 在另一个方向：完全免训练，雅可比迭代加 n-gram 池，候选从输入与历史中检索。常被引用的 4× 是 8 卡强扩展口径；n-gram 池的显存论文只给出定性描述，无实测值。

## 六、与其他方法的叠加

三条轴（KV、权重、token 数）可以叠用。EAGLE 与 gpt-fast int4 联合的数据是正例：FP16 下 55.1 → 100.2，int4 下 106.9 → 160.4，两轴收益都成立。Draft & Verify 将量化叠在自身方法上也是正例（bf16 1.53×、fp8 1.61×）。

同一张表中有一处反例：叠加稀疏化后，Draft & Verify 的相对加速比由 1.57× 降至 1.47×。论文的解释是基座模型同时被加速，相对收益随之下降。叠加收益需要实测，简单相加不成立。

文献中有一个未被验证的问题：投机解码与 KV 压缩是否正交。EAGLE 的草稿生成依赖 KV cache 的完整性，KV 压缩到 50% 或 2-bit 后草稿准确率可能下降，加速比随之降低。这一点只有实测能回答，已列入我的实验计划。

## 七、共同限制

这批方法全部只作用于 decode，prefill 不受益；KV 压缩那批中 DuoAttention 与 ShadowKV 都能改善 prefill，两批形成互补。

batch 增大时收益下降：投机解码利用批量未占满的算力，批量占满算力后收益消失。EAGLE 实测 bs 1→4 时，LLaMA2-Chat 70B 从 3.01× 降至 2.40×。适用场景因此是单请求、低并发的延迟敏感任务；大 batch 吞吐场景下收益有限。

## 八、小结

按训练与部署成本排列：Lookahead 免训练，n-gram 池占显存；Medusa 只训解码头，已并入 vLLM / TRT-LLM；EAGLE 按 target 各训一份草稿（0.24B~0.99B），代码完整；LayerSkip 需自训权重，不占额外显存；Draft & Verify 免训练但代码链接未核实。

引用纪律：接受率阈值 35%~45% 在一手文献中查不到出处，只见于二手整理，写进报告前需要回原文核对或自测确认。
