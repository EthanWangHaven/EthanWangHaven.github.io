开始读文献之前需要先回答一个问题：推理时间到底花在哪。这个问题不先量化，后面选方法就没有依据。这篇笔记把第一批文献（6 篇，以实测和建模为主）的归因结论，与我在 A800 上实测的三组数据放在一起。系列后面三篇的 KV Cache、投机解码、权重量化，都能对应到这里的结论。

## 一、阶段耗时：decode 占 95% 以上

LLM 推理分两个阶段。prefill 一次前向处理整条 prompt，所有 token 并行计算，矩阵乘的 m 维大，属于计算密集；decode 每次前向只产出一个 token，矩阵乘退化为矩阵向量乘（GEMV），属于访存密集。

Mind the Memory Gap（arXiv:2503.08311）在 H100 上用 Nsight 逐 kernel 实测，两阶段时间占比（表 I，两列之和恒为 1.00）：

| 模型 | prefill | decode |
|---|---|---|
| OPT-1.3B | 0.03 | 0.97 |
| OPT-2.7B | 0.05 | 0.95 |
| Llama-2-7B / 13B | 0.05 | 0.95 |

Cross-Layer 在 A100 80GB 上测得同一量级（0.95~0.97），两篇可以交叉印证。优化的重心因此全部落在 decode。

引用这个占比需要带一个口径说明。测量在 offline 模式下进行，profiler 强制所有请求先跑完 prefill、再统一进入 decode，真实服务里两阶段是交错的。论文正文没有披露这一点，说明出自配套 vLLM fork 的 README。因此 95% 是表征性数字，不能当作某个具体服务的 profile 结果。

## 二、decode 的瓶颈：显存带宽

decode 每一步的操作：把整个模型的权重从显存（HBM）读入片上缓存，与一个 token 做乘加，产出一个结果。读取量固定，产出只有一个 token，算术强度（每读 1 字节执行的运算数）因此极低。LLM Inference Unveiled 给出的范围：

$$
\text{AI}_{\text{decode}} \in [0.25,\ 1.75]\ \text{OPs/byte}
$$

两张目标卡的转折点（算力峰值 ÷ 带宽峰值）：

| 卡 | 架构 | 显存 | 带宽 | 转折点 |
|---|---|---|---|---|
| A800 80GB | Ampere sm80 | 80 GB | 约 2.04 TB/s | 约 153 OPs/byte |
| RTX 4090 | Ada sm89 | 24 GB | 约 1.008 TB/s | 约 164 OPs/byte |

算术强度比转折点低两个数量级。decode 阶段 SM 大部分时间在等数据，瓶颈在显存带宽。

Mind the Memory Gap 的实测给出了直接证据：decode 阶段 DRAM 读带宽均值 48%~77%、峰值 93%~99%；写带宽只有 1.82%~5.56%；算力利用率 decode 大部分时间低于 20%，全程实测算力只到峰值的 3.5%~3.8%（论文只给绝对值，百分比是回算值）。带宽接近峰值、算力接近闲置，这就是访存墙。

这篇论文自身的数字也需要核对。表 II 的算力峰值 25.6 TFLOP/s 来自仓库出图脚本，脚本把 Nsight 的 ffma 与 dfma 指标弄反，实际取到的是 FP64 峰值，比 H100 PCIe 的 FP32 峰值（51.2 TFLOPS）低约一倍，因此"离 roofline 差几个数量级"的表述被放大了。定性结论不受影响，具体数字引用前需要回原文核对。

## 三、三条瓶颈与对应方法

把上述结论拆分，得到三条互相独立的瓶颈，分别对应三类方法：

```
① 权重读取      每步读取全部权重（7B bf16 约 15 GB）→ 权重量化
② KV Cache 搬运  每步读取整条 KV cache，随长度与 batch 线性增长 → KV 压缩
③ 自回归串行     一次读取只产出一个 token → 投机解码
```

②与③正交：前者改变每次读取的字节数，后者改变每次读取产出的 token 数。①与②也正交：一个在权重侧，一个在缓存侧。正交说明可以叠用，但叠加的收益需要实测，第三篇有一个具体反例。

## 四、A800 实测

文献的实测平台全部是 A100 / H100 / V100，A800 与 RTX 4090 上没有任何已发表数据。这是 22 篇文献读完之后最直接的空白，也是我先跑 baseline 的原因。

平台：单卡 A800 80GB PCIe 独占，vLLM 0.19.0，torch 2.10.0+cu128，Qwen2.5-7B bf16，`temperature=0`。

### 4.1 batch 扫描

输入 96 token（各请求互不相同，前缀缓存关闭），输出 512 token：

| batch | 输出 tok/s | 单请求 tok/s | 相对上档 |
|---:|---:|---:|---:|
| 1 | 94.8 | 94.8 | — |
| 2 | 190.2 | 95.1 | 2.01× |
| 4 | 383.8 | 96.0 | 2.02× |
| 8 | 738.0 | 92.2 | 1.92× |
| 16 | 1,422.8 | 88.9 | 1.93× |
| 32 | 2,638.0 | 82.4 | 1.85× |
| 64 | 4,351.4 | 68.0 | 1.65× |

batch 1 到 8 接近线性，说明这一段带宽未饱和；16 之后增益衰减，32 到 64 只剩 1.65×，同时单请求速度从 94.8 降到 68.0（−28%）。与 Mind the Memory Gap 在 H100 上的定性结论一致：增大 batch 不会把瓶颈从访存转移到算力，只会让带宽逐步接近饱和。

### 4.2 上下文扫描

单请求，输入从 1K 到 32K，输出 128 token：

| 输入 token | 输出 tok/s | 相对 1K |
|---:|---:|---:|
| 990 | 92.3 | 100% |
| 4,095 | 91.9 | 99.6% |
| 8,190 | 89.6 | 97.1% |
| 16,380 | 85.3 | 92.4% |
| 31,995 | 80.3 | 87.0% |

上下文增大 32 倍，速度下降 13%。roofline 在最右一档的预测值为 82.4，实测 80.3，误差 2.6%。roofline 对 decode 阶段的预测精度可以支撑后续实验的预筛。

### 4.3 KV 读取占比与解码吞吐

固定 batch = 32，只改上下文长度，把每步读取量拆为权重与 KV 两部分：

| 上下文 | KV 读取 | 权重读取 | KV 占比 | 解码 tok/s | 相对最短 |
|---:|---:|---:|---:|---:|---:|
| 96 | 0.63 GB | 15.3 GB | 4% | 2,638 | 100% |
| 900 | 1.6 GB | 15.3 GB | 9.5% | 2,568 | 97.4% |
| 15,975 | 28.6 GB | 15.3 GB | 65% | 1,211 | 45.9% |

KV 占比从 4% 到 65%，解码吞吐下降 54%。这组数据给出方法选择的一维判据：KV 占比低于 10% 时权重读取主导，应做权重量化，KV 压缩的收益上限只有个位数百分比；高于 65% 时 KV 读取主导，压缩空间最大；中间区间两者都重要，交叉点需要实测，文献中没有这一区间的数据。

单独看 batch 或单独看上下文都会误判，决定性的量是两者的乘积带来的 KV 读取占比。

### 4.4 prefill 吞吐

前缀缓存关闭，16K 输入，输出 256 token。prefill 稳定在约 10,000 tok/s，对应 7B 模型约 45% 的算力利用率，与 decode 不到 4% 对照，验证了 prefill 计算受限、decode 访存受限的划分。

按 KV 容量上限（1,022,400 对 1,021,536）推测，batch 64 会出现性能断崖；实测只比线性外推慢 5%：

```
48 ÷ 32 = 1.500   → 实测 1.499  线性
64 ÷ 48 = 1.333   → 实测 1.401  慢 5%
```

原因是 chunked prefill（每块 16,384 token）将超出的块排队处理。Cross-Layer 在 A100 上观测到的"显存越界 → 重算 → 延迟尖峰 93.2 s"是在未启用分块预填的配置下测得，两者并不矛盾。但"显存越界即断崖"在 chunked prefill 下不成立，写报告时需要注明配置。

### 4.5 前缀缓存对测量的影响

实验早期用同一段 prompt 复制 32 份做 batch 扫描，wall time 为 6.8 s；改为互不相同的 prompt 并关闭前缀缓存后，同配置为 51.1 s，相差 7.5 倍。原因是 vLLM 默认开启 prefix caching，相同 prompt 的 prefill 被去重，测得的吞吐不含 prefill。

此后每个吞吐数字同时记录四项：prompt 是否互异、前缀缓存开关、输入输出长度、测量的阶段。同一配置重复三次，结果差异在 0.5% 以内。

## 五、结论

三组实测与文献归因一致：decode 占总时间 95% 以上；decode 的算术强度比两张卡的转折点低两个数量级，属于访存受限；瓶颈可拆为权重读取、KV cache 搬运、自回归串行三条。KV 读取占比是方法选择的起点，占比从 4% 升到 65% 时解码吞吐下降 54%。
