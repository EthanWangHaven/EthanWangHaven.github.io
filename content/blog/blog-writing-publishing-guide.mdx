这份笔记记录我从创建文章、插入图片/链接、本地预览、推送到 GitHub 的完整流程。



## 一、新建一篇文章

### 1.1 手动创建

在 `content/blog/` 目录下新建 `.mdx` 文件。文件名用英文 + 连字符，因为文件名会成为 URL 的一部分。

```
content/blog/your-article-name.mdx
```

好的命名示例：

```
content/blog/docker-usage-guide.mdx
content/blog/python-logging-best-practices.mdx
```

避免的命名：

```
content/blog/笔记123.mdx
content/blog/文章.mdx
```

## 二、文章 Front Matter（元信息）

每篇文章开头都要有一段 `---` 包裹的 YAML 元信息，完整模板如下：

```yaml
---
date: "2026-07-01T18:00:00+08:00"
draft: false
title: 文章标题
categories:
  - 分类名
tags:
  - 标签1
  - 标签2
  - 标签3
description: 文章简介，显示在卡片和详情页
---

这里开始是文章正文……
```

### 各字段说明

| 字段 | 说明 | 示例 |
|------|------|------|
| `date` | 发布日期时间 | `"2026-07-03T18:00:00+08:00"` |
| `draft` | `true`=草稿（不显示），`false`=发布 | 写完确认后改为 `false` |
| `title` | 文章标题，支持中文 | `"Pytest 从入门到企业实战"` |
| `categories` | 分类，决定文章出现在哪个分类页 | `["Blog"]` |
| `tags` | 标签，多个标签换行写 | `["Next.js", "Markdown"]` |
| `description` | 文章简介，显示在卡片和详情页 | `"系统梳理 RAG 检索链路优化..."` |

> **注意**：Front Matter 使用 YAML 格式（`---` 分隔），不使用 TOML 格式（`+++` 分隔）。

### 关于 description（文章简介）

`description` 字段会显示在：
- 博客列表页的卡片中（最多 2 行）
- 文章详情页标题下方

如果没有 `description` 字段，系统会自动从正文内容提取前 100 字作为摘要。

### 当前已有的分类

| 分类 | 说明 |
|------|------|
| `Blog` | 博客搭建、写作相关 |
| `Hyperparameters Tuning` | 模型训练调优 |
| `Dev Tools` | 工程开发工具 |
| `LLM Fine-tuning` | 大模型微调框架 |
| `Agent Development` | AI Agent 架构 |
| `RAG` | 检索增强生成 |
| `Deep Learning` | 深度学习基础 |
| `日本語学習` | 日语学习 |

如果现有分类都不合适，直接在 `categories` 里写一个新的分类名，系统会自动生成对应的分类页面。

## 三、MDX 写作规范

### 3.1 标题层级

```markdown
## 二级标题（文章中最大的标题）
### 三级标题
#### 四级标题
```

> 注意：不要用 `# 一级标题`，文章标题已由 Front Matter 的 `title` 渲染，正文中再用 `#` 会重复。所有标题会自动生成锚点链接。

### 3.2 文字样式

```markdown
**加粗文字**
*斜体文字*
`行内代码`
> 引用块
```

### 3.3 列表

```markdown
- 无序列表项 1
- 无序列表项 2

1. 有序列表项 1
2. 有序列表项 2
```

### 3.4 代码块

``````markdown
```python
def hello():
    print("Hello, World!")
```

```bash
pip install ms-swift -U
```

```json
{
    "name": "example",
    "version": "1.0.0"
}
```
``````

### 3.5 表格

```markdown
| 列1 | 列2 | 列3 |
|------|------|------|
| 内容 | 内容 | 内容 |
| 内容 | 内容 | 内容 |
```

### 3.6 插入链接

```markdown
[链接文字](https://example.com)

# 引用内部文章
[我的另一篇笔记](/blog/slurm-usage-guide)
```

### 3.7 插入图片

**第一步**：把图片文件放到 `public/images/` 目录下。

比如把截图保存为 `public/images/example-screenshot.png`。

**第二步**：在文章中这样引用：

```markdown
![图片描述](/images/example-screenshot.png)
```

图片引用路径相对于 `public/` 目录。`public/images/example.png` 对应引用路径 `/images/example.png`。

完整例子：

```markdown
## 配置界面

以下是 Claude Code 插件的配置截图：

![Claude Code 配置界面](/images/claude-code-config.png)

配置完成后点击保存即可生效。
```

> **图片命名**：建议用英文 + 连字符命名，清晰描述图片内容，如 `hyper-tuning-1.png`、`warmup-cosine.png`。

> **图注**：在图片下方紧跟一行斜体文字即可自动居中显示为图注：
>
> ```markdown
> ![图片描述](/images/example.png)
>
> *图：这是图片标题说明*
> ```

### 3.8 数学公式

使用 `$...$` 行内公式，`$$...$$` 块级公式：

```markdown
行内公式：$E = mc^2$

块级公式：

$$
\mathcal{L} = -\sum_{i=1}^{N} y_i \log(\hat{y}_i)
$$
```

## 四、本地预览

写完文章后，启动开发服务器检查效果：

## 五、推送到 GitHub

### 5.1 配置代理（公司网络需要）

```powershell
git config --local http.proxy http://proxy.nevint.com:8080
git config --local https.proxy http://proxy.nevint.com:8080
```

### 5.2 提交并推送

```powershell
cd C:\Users\ethan.wang18\Desktop\my-blog\my-blog-next

# 查看有哪些改动
git status

# 添加所有改动
git add .

# 提交（写清楚做了什么）
git commit -m "New post: 文章标题"

# 推送到 GitHub
git push origin main
```

### 5.3 自动部署

推送到 GitHub 后，GitHub Actions 会自动构建并部署。进入 [Actions 页面](https://github.com/EthanWangHaven/EthanWangHaven.github.io/actions) 查看构建状态：

1. 等待黄色圆圈变绿色对勾
2. 1-3 分钟后访问 `https://EthanWangHaven.github.io` 看效果

> 有时 Actions 跑完了但网页显示旧版本，按 `Ctrl + F5` 强制刷新浏览器缓存即可。

## 六、换电脑后继续写作

### 6.1 新电脑环境准备

只需要两样东西：

- **Git**：用于拉取、推送仓库代码
- **Node.js 18.18+**：运行 Next.js 开发服务器

Node.js 下载地址：https://nodejs.org/

### 6.2 配置 Git 身份

```powershell
git config --global user.name "EthanWangHaven"
git config --global user.email "your-email@example.com"
```

### 6.3 克隆博客仓库

```powershell
# 克隆到本地
git clone https://github.com/EthanWangHaven/EthanWangHaven.github.io.git

# 进入目录
cd EthanWangHaven.github.io

# 安装依赖
npm install
```

仓库里已经包含了所有文章、组件、配置，不需要额外下载任何东西。

### 6.4 本地预览

```powershell
npm run dev
```

浏览器打开 `http://localhost:3000` 即可看到与原来电脑完全一致的博客。

### 6.5 新电脑上写文章并发布

```powershell
# 1. 拉取最新代码
git pull origin main

# 2. 在 content/blog/ 下新建 .mdx 文件并编辑

# 3. 提交并推送
git add .
git commit -m "New post: 文章标题"
git push origin main
```

### 6.6 多设备协作注意事项

如果两台设备都写文章，操作顺序很重要：

```powershell
# 每次开始写之前，先拉取远端最新代码
git pull origin main

# 写文章、提交
git add .
git commit -m "xxx"

# 推送
git push origin main
```

如果两台设备同时改了同一个文件再推送，Git 会报冲突。优先保留内容更全的版本即可。
