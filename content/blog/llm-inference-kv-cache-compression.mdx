上一篇给出判据：KV 读取占比超过 65%（长上下文加大 batch）时，KV cache 的读取才是每步访存的主导项，KV 压缩在这个区间才有空间。这篇整理围绕 KV cache 的 8 篇文献。

现有方法分五类，各自减少的对象不同：碎片、内容、注意力头、位宽、存储位置。类别之间可以叠用，但数字口径不可互换。

## 一、PagedAttention：内存管理

PagedAttention（SOSP '23）不减少 KV 总量，处理的是显存碎片。现有系统按请求的最大可能长度预分配连续显存，实测只有 20.4%~38.2% 的 KV 显存存放了 token 状态，其余为内部碎片、外部碎片与预留。PagedAttention 将 KV 切成固定大小的块，非连续存放、按需分配，逻辑块到物理块的映射由块表完成（类比操作系统的页表）；块表之上再加引用计数与写时复制，使并行采样、beam search 等一个 prompt 派生多条序列的场景可以共享 KV。

结果：吞吐较 SOTA 提升 2~4×，延迟相当。两点需要注明：2~4× 是吞吐口径，单请求延迟基本不变；PagedAttention 已是 vLLM 的默认行为，对比实验中它属于 baseline，不能再计作一项加速手段。另外作者自陈分页注意力核引入 20~26% 的额外延迟开销，这是该方法的代价。

## 二、驱逐 / 稀疏：H2O、SnapKV、Ada-KV

驱逐类的共同假设：注意力集中于少数 token，其余可以丢弃。三篇的差异在评分方式、评分时机与预算分配。

H2O（NeurIPS 2023）的两个观察：预训练模型的注意力矩阵推理时稀疏度高于 95%；token 的累积注意力分数服从幂律分布，少数重击者（heavy hitter）贡献大部分注意力值，删除它们精度骤降。策略为保留重击者与最近窗口，每步按累积分数贪心淘汰最低分者，并给出 dynamic submodular 的理论界。20% 预算实现 5× KV 压缩，多数任务精度持平。

H2O 的两处局限由后续工作指出：只压缩 decode 新增的 KV，不覆盖 prompt 侧，而长 prompt 场景下 prompt 的 KV 占大头；评分需要先计算完整的注意力矩阵，这一步本身有开销。

SnapKV（2024）同时处理这两点。观察：各注意力头对 prompt 的关注模式在生成开始前即可由 prompt 末端的观察窗口识别，并在生成过程中保持一致。做法是在观察窗口内对 prefix key 投票取 Top-k，再做 1D pooling 保留邻域，避免纯 Top-k 将上下文切碎（论文的表述是"只留区号、丢了号码"）。全程 test-time，免微调。16K 输入下生成加速 3.6×，LongBench 上容量 1024 时压缩 92%、4096 时 68%，精度接近无损。压缩率与精度由容量超参控制：1024 换 92% 压缩，4096 换 68%，预算选择直接体现在精度上。

Ada-KV（NeurIPS 2025）指出 H2O 与 SnapKV 共同的隐含假设不成立：每头相同的 KV 预算。各头的注意力集中度差异很大，多数头 top-5% 即覆盖绝大部分注意力权重，均匀预算造成稀疏的头浪费预算、分散的头损失精度。Ada-KV 将一层内所有头的注意力权重拼接后做一次全局 Top-k，按各头入选个数确定预算，不增加排序开销。效率与均匀分配持平，收益在精度侧：80% / 20% 预算下，Ada-SnapKV 将 SnapKV 的分数从 87.59 / 44.02 提升到 92.67 / 53.29。它是插件式方法，价值在精度侧。

引用这一线的数字需要带基线。H2O 的 29× 的对比对象是 DeepSpeed ZeRO-Inference 与 HF Accelerate 两个 CPU offload 方案，对同类系统 FlexGen 只有 3×。Scissorhands（同属驱逐线，按重要性持续性假设做固定预算管理）全篇没有 wall-clock 数据，只能引用"KV 压缩 5×"，不能写"加速 5×"。Scissorhands 还有一个自我反例：随机初始化的 OPT 上重复注意力模式消失，说明重要性持续是训练产物，不随架构保证成立。

## 三、DuoAttention：按注意力头分类

驱逐方法在 token 维度处理，对所有注意力头一致。DuoAttention 在头维度区分：少数 retrieval 头需要对全部 token 的完整注意力，多数 streaming 头只需 attention sink 加最近窗口。retrieval 头保留全量 KV，streaming 头只保留常数窗口，显存占用不随序列增长。

这个设计有两个特点。streaming 头的处理不依赖 decode 阶段的注意力分数，因此可以同时加速 prefill，token 驱逐类方法做不到这一点。实现上离线重排 Q/K/V 输出通道，将两类头排成连续块，不修改 attention kernel，因此兼容 FlashAttention-2、GQA 与量化。

数据：KV 显存降低 2.55×（MHA）/ 1.67×（GQA），decode 提速 2.18× / 1.50×，pre-filling 提速 1.73× / 1.63×。

复现层面它是八篇中门槛最低的：官方仓库发布 6 个 7B / 8B 模型的预计算 pattern，原需 8×A100 数小时的标定可以跳过。两处版本问题需要记录：Mistral-7B-v0.3 的 pattern 文件有误（含 32 层，模型实际 36 层，issue #23）；transformers 需锁定 4.45.2（issue #18，否则报 cache_position 相关错误）。标定产出的 gate 值是模型权重的属性，与 GPU 型号无关，因此其它卡上标定的 pattern 可直接用于 A800 / 4090。

局限：短上下文收益很小（streaming 头仍保留约 80 个 sink 与 recent token）；retrieval 头的计算与显存不减少，只按比例缩放。

## 四、KIVI：KV cache 的 2-bit 量化

KIVI（ICML 2024）处理位宽。KV 量化与权重量化的差别在于流式约束：权重可以离线用二阶信息优化，KV 每步生成即新增、必须立即量化，只能用 round-to-nearest。在此约束下 per-tensor 量化因离群值失效：key 的少数固定通道幅值极大，统一 scale 偏大，正常通道的分辨率不足。

KIVI 的核心是不对称设计：key 按 channel 分组量化（组大小 32），将离群值限制在各自组内；value 无离群模式，按 token 量化，利用注意力稀疏性将误差限制在单个 token 内。为兼容流式，KV 拆为两部分：每 32 个 token 一组的量化存储，加最近 128 个 token 的全精度滑窗（per-channel 量化跨 token 无法流式，滑窗解决这一问题）。

数据：key 分组后注意力相对误差 47.0 → 9.6；2-bit 在 Llama-2-7B 的 CoQA 上 63.05 对 63.88；峰值显存降低 2.6×（含权重，单看 KV 降幅更大）；吞吐 2.35~3.47×。

失效条件：Falcon-7B（MQA，单 KV 头）上 2-bit 掉点大，需退到 4-bit；GSM8K 等难推理任务去掉全精度滑窗后精度崩溃（伪量化仅 5.76）。Qwen2.5-7B 是 GQA 结构，KIVI 的 2-bit 结论是否适用需要先自行验证。

## 五、ShadowKV：低秩与卸载

ShadowKV 的设计基于一个结构观察：pre-RoPE 的 key 近似低秩，只存低秩投影（rank 160）；value 不低秩，卸载到 CPU，使用时在线重建。卸载取数慢，用多流重叠将 value 的 PCIe 传输与 key 的低秩重建重叠；另存 0.2%~0.3% 的难近似 outlier 块作为 GPU 上的高精度缓存，补偿低秩与均值化带来的精度损失。

数据：KV 显存理论上限降低 7.08×，实测 6× 压缩不掉精度；吞吐最高 3.04×。两处口径：常被引用的"等效带宽 7.2 TB/s = 3.6× A100"是等效口径，端到端吞吐是 3.04×；前提是 CPU 内存能容纳完整 value cache，长序列大 batch 时达数十 GB，显存压力只是转移到主机，总量并没有消失。论文没有独立的 Limitations 章节，以上几点从正文归纳。

## 六、横向对照

| 论文 | 减少的对象 | 压缩 / 显存 | 吞吐或速度 | 精度 |
|---|---|---|---|---|
| PagedAttention | 碎片 | 利用率 20~38% → 近 100% | 吞吐 2~4× | 无损失 |
| H2O | 内容 | KV 5× | 吞吐至多 29×（对 CPU offload 基线） | 20% 预算持平 |
| SnapKV | 内容 | 92%（1024）/ 68%（4096） | 生成加速 3.6×，内存效率 8.2× | 接近无损 |
| Scissorhands | 内容 | 最多 5× | 无 wall-clock 数据 | 15~30% 保留仍保持 |
| DuoAttention | 按头区分 | 2.55× / 1.67× | decode 2.18× / 1.50× | 近无损 |
| KIVI | 位宽 | 显存 2.6×（含权重） | 吞吐 2.35~3.47× | 2-bit 近无损（除 MQA） |
| ShadowKV | 存储位置 | 6×（上限 7.08×） | 吞吐 3.04× | 不掉 |
| Ada-KV | 内容 + 预算 | 同预算下精度更高 | 与 SnapKV 持平 | 同预算下更高 |

表中压缩比（显存 / 容量）、吞吐、单请求延迟是三个不同的量。Scissorhands 是唯一没有时间侧数据的一篇，其 5× 最常被误读为加速比。

## 七、适用边界：长上下文

除 PagedAttention 外，这批方法的收益全部出现在长上下文。原因可由上一篇的实测解释：短上下文小 batch 时 KV 只占每步访存的 4%~9.5%，全部压缩的收益上限也只有个位数百分比。

实验设计上，先在 4090 上扫描上下文长度，找到显存接近 24GB 的档位：边界低于 8K 则主线转为权重量化（第四篇），高于 16K 才做 KV 压缩。这一边界不通过公式估算：vLLM 的 `gpu_memory_utilization` 预留、KV 分块与 prefix caching 使实际占用与理论值有明显偏差，估算值会引入系统性偏差。

## 八、小结

五类方法的区分：分页减少碎片，驱逐减少 token，DuoAttention 按头区分，KIVI 降低位宽，ShadowKV 改变存储位置。引用任何数字前核对三件事：基线、口径、平台。
